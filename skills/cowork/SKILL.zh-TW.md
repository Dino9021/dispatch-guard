# Cowork：幾個 session、一個主人 —— 一棵工作樹，或兩台機器

由幾個共用同一個 repository、同一位主人的 session 寫成。每一行都是付過代價學到的。
這裡沒有任何專案、機器、帳號、路徑、產品或人名 —— 一條規則若換到別處就不成立，它就不屬於這個檔。

⛔ **跨「機器」時，本頁其餘部分預設存在的機制都不存在** —— 沒有共用的 session 目錄、沒有對方的
心跳、沒有 `SendMessage` —— 而你為了取代它們所搭的管道，可能在某一個方向壞掉卻**兩邊都不報錯**。
第 13 條是底線，`reference/cross-machine.md` 是全部；而且值得在**搬家之前**讀，不是搬到一半才讀。

**觸發的是「情境」，不是「字眼」。** 只要參與的不只一方 —— 同一個 repository 有不只一個 session（同時，
或一個接一個做同一件事）、不只一台機器、或工作跨 repository／跨專案 —— 就該載入；擁有者把同一件事轉述給
好幾個 session 也算。問題聽起來只是在複製檔案、用 git、權限、或「接下來該檢查什麼」都沒關係：畫面裡一出現
第二個 session、機器、repository 或專案，就屬於這裡。

整頁讀完。要做某件事之前，再開對應的 reference 檔。這個 skill 裡每一個指標都指向 plugin 內
出貨的檔案 —— `skills/*/SKILL.md`、`PROTOCOL.md` —— 絕不指向只有某一台機器才有的檔案。

## 十三條規則

只讀一段的話，讀這一段：少了它們，真的出過事。

1. **先認領，再產出。** 同一則指示同時到達每個 session，會生出四份同一節的草稿。在一份共用、
   只能追加的紀錄上寫一行「我拿什麼」；只拿沒人認領的。**工具也要認領**，不只是交付物的段落 ——
   兩個人各造同一把尺，在任何地方都不會撞到。
2. **先報到、只登記自己、用 id 定址 —— 絕不用名字。** session 名字**幾分鐘**就會變，而且會被**回收**：
   送給被回收的名字，訊息會**成功、無聲地**送到另一個 session —— 比過期更糟，過期至少會報錯。所以每個
   cowork session 的第一件事是寫**自己的報到檔**（一人一檔、以 session id 命名、放在固定的共用目錄）；
   收到擁有者指定的代號時，要回「收到，我的代號是 S4，以後請用 @S4 稱呼我」。傳訊息用 `[ref]`／
   session id，送出前先確認那個名字對應的 id 仍等於對方報到檔上的 id。名冊是歷史，不是通訊錄。
3. **一份只能追加的共用紀錄，更正也用追加。** 不改先前的任何一則，連自己的也不改。「某個錯答案
   曾經被相信過」通常是檔案裡最有用的資訊。⭐ **有 hook 強制：** 第一個標題含 `append-only`（或有一行只寫
   `<!-- append-only -->` 註解）的檔案只能變大 —— 見下方「hook 強制什麼」。
4. **問主人的問題經由單一 session 匯集，並用一個檔案備援那個匯集點。** 匯集讓主人不必同一題答三次；
   檔案讓待答的問題不會跟著那個 session 一起死掉。
5. **問主人的時候絕不用代名詞。** 「那五個」「壞掉的那個」「舊的那支腳本」—— 每一個都換成完整名稱。
   寫不出名字，就表示你還沒調查完，問題還不能問。
6. **問之前先搜，開工之前先搜。** 歸檔、commit、寫交接保證的是「找得到」，沒有一個保證「被讀過」。
   最貴的失敗是重做別人已經做完、歸檔的東西。「怎麼搜」才能讓空結果有意義，在 `unattended-work` §11。
7. **做完沒回報不算做完。** 先把結果落到共用產出物，再告訴任何人做完了。在沒人讀得到的地方是對的，
   等於沉默。
8. **執行才能宣稱，不准用推理。** 正本只有一份：`unattended-work` §10。這個 skill 加上的是：它同樣
   約束**同事的**宣稱 —— 要依賴一份承重的報告之前先自己重量一次（`owner-and-reporting.md` 2.9）。
9. **空結果是一個宣稱 —— 而一道對照不夠。** 正對照、錨定路徑、不靜音的錯誤、兩種樣式，在
   `unattended-work` §11。這個 skill 加上另外三道：帶目標形狀、必須觸發的**樣式**探針；必須**不**觸發
   的**相似樣本**；每次新生的**負向**哨兵。「大部分規則有反應」不是對照。
10. **寫入先驗位元組，再驗結構。** 附加型：`after == before + body`。取代型：驗證 reference 裡的五步。
    位元組證明寫進去了沒壞；結構檢查（數節數、標題、欄數）證明寫到了對的地方。兩者互補。
11. **宣告任何東西不見之前，用內容搜、不用檔名搜 —— 而且絕不轉達自己沒查過的「缺席」。** 實測：
    一小時內三個人各自宣告某件工作不存在；三件都在，只是換了名字或在別的目錄。轉達「X 還沒做」會把
    一次失敗的搜尋變成所有人的事實。
12. **講清楚你的「沒答案」是哪一種。** `UNKNOWN`（查了；資料分不出）／`NOT-ASKED`（來源存在；決定不查）／
    `UNCONFIRMED`（查了一部分）。把三種混成一種，問題就永遠不會再被問。
13. **在你依賴一條管道之前，先證明你「寫得進去」，而且兩個方向分開量。** 一方只讀得到、寫不進去的板子，
    就是那一方無法回話的板子；而另一方會把這份沉默讀成「他還沒開始」。實測：兩個 session 就這樣卡死
    將近一小時，**雙方的行為都正確，雙方都沒有收到任何錯誤**，最後是主人手動修權限才解開。
    所以在第一則真正的訊息之前，兩邊各追加一行有日期的「管道測試」，並各自確認看得到對方那一行；
    而等超過幾分鐘，要先當成**權限**假設，不是耐心問題。任何「送達的東西」也一樣：跨機複製之後
    第一個檢查是「我能不能寫」，不是「雜湊對不對」—— 一棵位元完全正確卻不可寫的樹，會讓後面每一步
    都失敗、而且每一步的錯誤都長得不一樣，讀起來像五個互不相干的 bug。

**每一條規則的完整說明在哪** —— 直接翻到指名的節，不要翻目錄：

發生，就別再寫了，做一個會拒絕繼續的東西。這個檔案裡每一條規則，都被寫它的人在寫它的那一小時
裡違反過至少一次。其中兩條現在是閘門。

## hook 強制什麼

dispatch-guard 的 hook 看得到這台機器上每個 session 的每一次工具呼叫，而這十三條裡有兩條在那裡
拒絕很便宜。**一次被拒絕的呼叫是規則在運作，不是 bug。** 兩個 guard 都 fail open（guard 自己壞掉
會記錄並放行）、對 plugin 安裝前就開始的 session 只提醒不拒絕、每個決定都寫進 log、各有自己的開關。

**`guard_append_only`（第 3 條）。** 一個檔案在前 2 048 位元組內，第一個標題行含 `append-only` /
`append only`，或 HTML 註解 `<!-- append-only -->` **獨佔一行**，就是它自己宣告只能追加。正文提到這幾個字
不算 —— 包括這一句在句子裡引用那個註解，也不算。
對這種檔案 hook 會拒絕：

- 內容不是以檔案現有文字開頭的 `Write`；
- `old_string` 不在檔尾、或 `new_string` 不以它開頭、或 `old_string` 在檔案裡出現超過一次的 `Edit`
  （不論有沒有 `replace_all` —— 工具只改其中一處，guard 分不出是哪一處；把錨點拉長成整個最後一則，
  不要只用最後一行）；
- 會截斷、就地改寫或移除它的 shell 指令：`> path`（含帶引號的路徑）、`sed -i`、沒有 `-a` 的 `tee`、
  `rm`、`truncate`、`cp` **蓋到它身上**、`mv` **來源或目的是它**、`Set-Content`、沒有 `-Append` 的
  `Out-File`、`Clear-Content`、`Remove-Item`、`Move-Item`、`Rename-Item`、`Copy-Item` **蓋到它身上**；
  同一條指令開頭的 `cd x &&`（或 `Set-Location`、`pushd`）會**取代**路徑解析用的目錄。

放行：建立這個檔案；`>>`、`tee -a`、`Add-Content`；`old_string` 是檔案的最後**一則**（長到只出現一次、
且結束在檔尾）、`new_string` 以它開頭的 `Edit`；把檔案**複製出去**。⚠ 複本會繼承標記 —— 快照請用新名字，也絕不複製回紀錄上。⚠ 一個就地
改寫檔案的程式（`python fix.py board.md`）、或刪掉它所在的整個目錄，看不到；guard 讀的是 shell 運算子
和檔案工具的輸入，不是程式做了什麼。

**`guard_cowork_first`（第 1–2 條）。** 當這個 repository 裡另一個 session 的心跳比 `peer_alive_min`
（預設 15 分鐘）新，而這個 session 沒有叫過 `dispatch-guard:cowork`，第一次 `Write` / `Edit`（任何檔案工具）/
`git commit` 會被拒絕**一次**，並說出 peer 數量。叫那支 skill 再重試；下一次呼叫無論如何都放行。
停在提示等輸入的 session 不會心跳，所以閒置超過 15 分鐘的 peer 不算；剛離開的 peer 會被算到最多
15 分鐘 —— 一次，之後對那個 session 不再。

⛔ **它只看得到同一台機器上的 peer。** 它讀的心跳是**這台**機器狀態目錄裡的一個檔，所以另一台機器上的
session 永遠不算 peer，這個守衛對它永遠不會觸發。⇒ 跨機任務**完全沒有東西會提醒你**，站在那裡的只有
第 13 條和 `cross-machine.md`。不要把這一節當成搬家時的保護。

開關：`guard_append_only`、`guard_cowork_first`、`peer_alive_min` —— 放在 plugin 的 `config.json`
或 `<repo>/.claude/dispatch-guard.json` 的 `dispatch` 底下。關掉的 guard 仍會記錄它本來會拒絕什麼。

## 失效形狀

一份目錄，讓下一個 session 叫得出形狀的名字，而不是重新發現一次。

| 形狀 | 長什麼樣 | 怎麼破 |
|---|---|---|
| 沉默的儀器 | 一個不會失敗的檢查，回報成功 | 同一次執行裡放一個正對照 |
| 假 0 | 路徑錯、過濾器錯或編碼錯，輸出空白 | 錨定路徑；不靜音錯誤；兩種樣式 |
| 規則太窄 | 一個什麼都不命中的規則，給出可信的 0 | 帶目標形狀的合成探針；每一條規則都必須觸發 |
| 規則太寬 | 對只是長得像的無辜資料自信命中 | 必須不命中的相似樣本，放在必須命中的那個旁邊 |
| 真命中、錯意思 | 真的命中，但在別的節或別的日子 | 讀命中處的脈絡，不是數字 |
| 單邊改動 | 分類器改了，只在你看的那一類檢查 | 引用任何數字之前，讀它會產出的每一類 |
| 換掉比較對象 | 複查有問題的儀器時，問題在你腳下換了 | 重述兩邊，再確認新指令仍然有那兩邊 |
| 位元組對、地方錯 | 一次寫入完美驗過一個錯的預期 | 位元組檢查旁邊加一個結果的結構檢查 |
| 只驗一半的護欄 | 一次突變只證明護欄在，不證明擋住你的是它 | 弄壞被保護的東西；再拿掉護欄，確認會溜過 |
| 存下來的數字腐爛 | 一個安靜地不再為真的數字 | 重算；或記下量測時間 |
| 沒有日期的紀錄 | 只有時間沒日期的時間戳，被當字串比大小 | 從檔尾往回走到已知標記；只有視窗真的跨日才允許跨一天 |
| 做之前先宣稱 | 寫了「完成」才發現失敗 | 做、驗、寫。順序不可反 |
| 修了咬我的那一個 | 補了一個呼叫端，同型的兄弟沒補 | 全樹搜同一個形狀，整族一起修 |
| 沒名字的警報 | 只說有幾個，從不說哪幾個 | 觸發當下就把識別碼帶進警報文字；事後查已經沒了 |
| 匿名工具 | 兩份輸出一模一樣，聲稱的修正無法驗證 | 第一行印版號；內容變版號就變 |
| 單點轉達 | 所有溝通都經過一個 session | 轉達旁邊保留一條持久的文字路徑 |
| 名字被回收 | 送給熟悉的名字，訊息成功送達 —— 送到另一個 session，沒有任何錯誤 | 用 `[ref]`／session id 定址；送出前確認名字仍對應到對方報到檔上的 id |
| 名字撞名 | 你的代號同時也是清單裡某個不相干（甚至離線）session 的名字 | 代號加前綴（`@S4`），就不會跟 runtime 名字撞 |
| 收攏不等於讀過 | 答案歸檔在沒人開的地方 | 問任何人之前先搜紀錄 |
| 改名讀成刪除 | 共用產出物在整理時「消失」 | 用內容搜 —— 大小、標題、雜湊 —— 而且不只搜你預期的那個目錄 |
| 過期的解釋 | 新證據被一個先前為真的說法吸收掉 | 看你要重用的那次檢查的時間戳 |
| 整理變成陷阱 | 改慣例後留下一個別人還在用的位置 | 移除共用位置是公告，不是整理 |
| 省略遇上重組 | 沒人寫：一個讓給另一個，另一個搬走了 | 在自己的作品旁邊逐條列出你依賴了什麼 |
| 草稿放在上線位置 | 半成品被載入、被當成品照做 | 在不會被載入的路徑工作；最後一步才搬到上線位置 |
| 大家都禮讓 | 「我不認領」講四次，任務就停了 | 禮讓要附一個到期預設值，寫明否則由誰做 |
| 兩套對的規則 | 兩套規則並存沒人發現，各自往反方向執行 | 讀產出物本身，不只讀關於它的說明；第一件事是回報那個不一致 |
| 無聲死鎖 | 兩邊都在等、行為都正確、沒有任何錯誤 —— 其中一方寫不進管道 | 第一則訊息之前先做雙向寫入測試；沉默超過幾分鐘＝權限 |
| 單向管道 | 「我聯絡不到你」被當成「根本沒有管道」 | 兩個方向分開量；出去不通不代表進來不通 |
| 到了卻不能用 | 雜湊驗過了，後面每一步卻各自用不同的方式失敗 | 複製之後第一個檢查是寫入測試，不是雜湊；能新建不代表能改既有檔 |
| 看不見被忽略的那一區 | 結構化搜尋回一組乾淨又可信的結果 —— 少了每一個被 ignore 的檔 | 搬家掃描關掉 ignore 規則，並用清單指名的「已知會中」路徑當對照 |
| 無聲的文字損壞 | 產生出來的訊息掉了分隔符號、多了看不見的控制字元 | 用檔案寫入工具，不走 shell heredoc；寫完用碼位掃，不要用看的 |
| 陽性對照沒跑到 | 乾淨的數字印出來了，緊接著陽性對照那一行崩掉 | 陽性對照沒印出來的乾淨結果是 UNCONFIRMED，不是乾淨 |

## 怎麼用這個檔

1. 新 session 加入共用樹：讀十三條規則，登記自己，讀最近的共用紀錄。然後 `reference/coordination.md`。
2. 回答任何關於活系統的問題之前：`unattended-work` §10–§11，然後 `reference/verification.md`。
3. **跟另一台機器上的 session 協作、或把專案搬到新硬體之前：`reference/cross-machine.md`，
   並且在**搬家之前**跑它開頭那份檢查清單。**上面每一項事前都很便宜、事後都很貴 ——
   寫入測試只要五條指令，省掉它的代價是兩邊互相沉默將近一小時。
4. 長時間或無人看管的任務之前：先 `unattended-work` 和 `dispatch-protocol`；多 session 多出來的部分
   在 `reference/longrunning.md`。
5. 事情看起來不對：先在上表找形狀，再推理。
6. 這個檔錯了，修正送進 dispatch-guard repository、由 plugin 更新送達 —— 絕不改已安裝的副本，也絕不
   在這個名字底下放第二個檔。**只有一份** —— 同名兩個檔就是擲硬幣，即使此刻一模一樣。
