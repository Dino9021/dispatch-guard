# 派發子任務（dispatch-protocol 正體中文對照）

> ⚠ **這是給人讀的參考翻譯，不是 skill 本身。**
> skill 只讀同目錄的 [SKILL.md](SKILL.md)，英文版才是唯一有效的依據。
> 英文版更新後這份可能落後；兩邊不一致時以英文版為準。

有一個 hook 強制執行其中吃重的部分，而且會**拒絕工具呼叫** —— 一次被拒絕的派工是規則在
運作，不是 bug。完整機制和誠實列出的強制缺口：`../../PROTOCOL.md`。

## 任務資料夾怎麼擺

在宣告的 `task_root`（預設 `<repo>/Memory/tasks/`，gate 在 session 開始時就建好 ——
不要自己挑別的位置，也不要問）底下建立你的任務資料夾：`<YYYYMMDD-HHMMSS-task-name>/`，
時間戳到時分秒。這個任務產出的每一樣東西都放在那裡：`prompts*.md`（每一份提示詞，**在任何
派工之前**）、`progress.md`（由 gate 寫）、`agent-NN-<subtask>.md` 報告、外部模型的原始擷取、
交接文件。

⭐ **檔案系統就是交接** —— 聊天輸出隨 session 一起死。
⛔ 絕對不要把憑證、金鑰、token 或機器識別碼寫進會被 commit 的資料夾。

## 暫存檔案

⭐ **子任務寫的每一個中間檔案，都放在任務資料夾裡它自己的目錄下：**
`<task_root>/<task>/scratch/<NN-代理或用途>/`。探測、擷取下來的指令輸出、寫一半的腳本、
下載的頁面、產生的測試素材 —— 全部，而且用它所屬的子任務或問題命名。

⛔ **不是系統暫存目錄、不是儲存庫根目錄，也絕對不是兩個子任務共用的路徑。**
兩個 agent 被告知「找個暫存的地方」，會挑到同一個位置，而第二個會清掉第一個的證據 ——
於是失敗的那一個，正好是檔案已經不見的那一個。

⚠ **這在這個 repo 自己的檢查程式上實測過**：每個子行程啟動時都清空共用的 scratch 目錄，
跑完整套之後只剩**最後一支**的檔案。

⭐ **子任務結束之後留著。** 它們不花什麼成本，而且是 agent 離開之後唯一能回答
「它到底看到了什麼」的東西。任務資料夾是整包刪除或封存的，scratch 不需要自己的清理規則。

⚠ **路徑要寫在提示詞裡。** 子任務推不出來；一個只被告知「把報告寫到 X」的 agent，
其他東西會亂放。⛔ 如果那個任務資料夾會被 commit，記得把 scratch 路徑 gitignore。

## 派工「之前」就選好模型

挑「做得動這個單位的最便宜模型」。`max_model_price`（預設 **5**）是子代理的模型每百萬
**輸入** token 最多可以花多少美元，超過就會被拒絕 —— ⭐ 所以在這裡決定，不要等被拒絕。

⭐ **價格「故意」不寫在這個檔案裡。** 一張打在 skill 裡的表，在有人發佈新版外掛之前
都不會更新；這個儲存庫就出過這個錯 —— 它手打的那張表把 Claude Haiku 3.5 標得比公告價貴，
而且錯了好幾個月。現在的表是從 Anthropic 官方定價頁解析成 `model_pricing.json`，並在背景更新。

⇒ **在你選之前，它會用兩條路送到你面前，你不用去查：**

- **session 開場的 context** 會寫出你可以派哪些家族、不可以派哪些，還有它們目前的價格；
- **每一份子任務提示詞前面被加上的那個區塊的第 7 條**帶著同一份清單，
  所以再往下派工的 agent 也被同樣的數字綁住。

要自己看完整的表：
`bash <plugin>/hooks/run.sh <plugin>/hooks/model_pricing.py --show`

⚠ **一個家族不是一個價格。** 寫**舊版本**可能比寫家族名貴好幾倍 ——
已退役的 opus 是目前 opus 的三倍。⭐ 優先直接寫家族別名。

⛔ `best` 解出來是 **fable**，也就是最貴的那個可選家族。`opusplan` 解出來是 opus。
`[1m]` 後綴不改變價格。`mythos` 有價格，但沒有任何 session 可以用別名選到它。
⭐ **不寫 `model` 永遠放行**，那時候子代理繼承這個 session 的模型 ——
那是安全的預設值，也表示永遠都有一條合法的派工路徑。

⚠ 如果開場的 context 說讀不到價格表，那這個 session 的上限**沒有在執行**。
不要把它回報成生效中。

## 六種會被拒絕的情況

1. **同時兩個派工。** 循序派工不需要任何許可，而且是預設做法；並行需要 owner 的核准，
   記錄在任務資料夾裡的 `PARALLEL-APPROVED`，數量要寫成 `parallel N`、`N=<n>` 或 `平行N`
   ⛔（單獨一個數字不算）。
2. **背景派工** —— 它會完全繞過計數。
3. **計畫還沒落到硬碟就派工**（`prompts*.md` 要比 session 開始時間新）。
4. **任何會大量生成 agent 的工具。** 沒有核准管道。
5. **用量判定為 STOP 時派工。**
6. **模型超過 `max_model_price`** —— 見上面那張表。⛔ 不要自己把上限調高，那是 owner 的設定。

⛔ **agent 會用三種說法把自己講過第 1 條 —— 沒有一種是例外：**

- 「這只是 review 而已」 —— ⭐ **兩個審閱者就是兩次派工**，第二個要等。
- 「這次情況特殊」 —— 只有 owner 訊息裡**明確寫出的數量**才算核准；「一起做」是**請求**，不是核准。
- 「我先丟到背景，之後再收」 —— 見第 2 條。

⭐ **核准 N 的意思是「同時最多 N 個活著」，而且是一批一批跑**（派 N 個、等**全部** N 個回來、
再派下一批 —— 不是「有人做完就補一個」的滑動視窗）。⚠ 核准會過期（預設 60 分鐘），
而且只對那個指名的任務資料夾有效。

**要申請數量的時候：** 寫好計畫和提示詞，告訴 owner 總共幾個、以及他們可以核准一個數量，
然後**立刻開始循序派工** —— ⛔ 絕對不要停在那裡等回答。

## 每一份提示詞

1. ⛔ **必須完全獨立** —— 執行它的 agent 沒有你的任何 context；每一個路徑、限制、驗收標準
   都要寫在本文裡。
2. **結尾要指名它的輸出檔案**，放在任務資料夾底下（gate 也是靠這個找到對應的計畫）。
3. ⛔ **要求報告「邊做邊寫」** —— 先把檔案建起來，每有一個發現就附加上去。
   ⚠ 一個在最後一次寫入之前就死掉的 agent，等於什麼都沒產出。
4. ⛔ **要寫出 `subagent_type`，而且要寫出這份提示詞需要它具備的能力** ——
   `type: general-purpose  ← 需要 Write：這份提示詞要它自己建立報告檔`。
   只寫型別名稱不帶任何資訊；⚠ 那句「需要什麼能力」，不先去查那個型別的工具清單就寫不出來。

⛔ **第 3 條只對「有辦法寫檔」的 agent 才是規則。** 2026-08-31 實測：一次 ADR 第二輪審查
被派成 `Explore` —— 一個唯讀型別。它建不出報告檔，於是把整份審查當成最後一則訊息回傳，
而它的驗證表格和其中五項發現**永久遺失**，因為那些內容在派工端從來沒收到的中間回合裡。
那次派工只寫了模型、完全沒寫型別，所以這個不匹配沒有任何地方可以現形。

⚠ **不要相信任何寫死在檔案裡的唯讀型別清單** —— agent 型別由使用者和 plugin 自行定義
（`.claude/agents/*.md` frontmatter、SDK `agents`），所以寫在這裡的快照會過期，然後開始說謊。
要看的是這個 session 為那個型別宣告的工具清單。只帶 `Bash` 的型別可以透過 shell 寫檔，不算問題。

⭐ **agent 回來之後，`ls` 一次它的提示詞指名的那個檔案。** 沒有檔案就是沒把事情做完，
不管那份摘要讀起來多乾淨。⚠ 真正守得住的是這一步：出問題的那個 agent *有*在第一行說了，
還是被漏掉，因為摘要看起來很正常 —— 檔案不存在看起來不正常。如果一個唯讀 agent 回傳了
本來該落在磁碟上的內容，下一個回合就把它逐字抄進任務資料夾，並且**在那個檔案裡**寫明
這是抄錄的、以及少了什麼。

## 用量：看那個「字」，永遠不要自己算數字

派一波之前跑 `<plugin>/hooks/usage.py --verdict`。

| 判定 | 意思 |
|---|---|
| **GO** | 可以自由派工 |
| **PACE** | 把手上的做完，不要再開新的一波 |
| **STOP** | 收尾、寫 `HANDOFF.md`、預約續跑（gate 會把兩條路都印出來）、結束這一輪 |
| **NO-DATA** | 把用量回報為 UNKNOWN，⛔ 絕對不要講一個數字 |

⛔ **永遠不要從原始百分比自己推算還剩多少。**

## STOP 之後的 HANDOFF.md

那是下一輪唯一拿得到的東西（重讀一次對話紀錄大約每 MB 要 95k tokens 而且完全沒有快取；
一份 3 KB 的交接文件約 800）。

六個段落：目標（獨立可讀）· 已完成（附上每一個產出路徑）· 下一步（不留任何待決定的事）·
試過但失敗（附理由）· 已經決定的事（不要再翻案）· 每一個路徑、指令與分支。

⛔ 不要有任何往回指的參照，永遠不要寫「接續之前的工作」。寫完跑
`resume.py --arm --task <task>`。⚠ 那個 200 字元的下限抓的是**空的**，不是**爛的** ——
品質是你的責任。

## 外部模型的執行

gate 看不到它們，所以這一條靠你自己守：把提示詞、記錄、輸出**原封不動**擷取進任務資料夾
（⭐ 是監督者去擷取，工具自己不會）。判定寫進 `progress.md`，⛔ 不要用編輯輸出檔的方式記錄。

## 如果你就是被派出去的那一個

用全力把你那一單做完 —— ⭐ **控速是派工者的決定，絕對不要自己減速。**
這些規則同樣約束**你**派出去的任何東西，每一層都是；觸發的是同一個 hook。
